灯灭之后

系统设计 · 光影潜行 中式怪谈 单文件 HTML · 零依赖 2026.09

特化于实时压力曲线的小品级守夜潜行：全流程 8 分钟一局——黑暗中备油、点灯、守夜，撑到鸡鸣。本文档展示创作思路、机制演化过程与关键设计决策。

一、创作思路：从一个核心循环出发

立项先定一句能被玩法验证的题眼：

为了延续安全，必须主动走出安全。

守夜人的处境天然承载这句话：灯油同时是视野、生命值、安全区货币三种资源——想看清更远，就要烧油；想保住油，就要摸黑；想获得永久安全区，就必须把油注入屋子中央的长明灯，然后离开它去黑暗里找下一份。安全不是被给予的状态，而是被消耗的资产。

由此展开三条设计主线：

  • 光照即机制：Canvas 遮罩用 destination-out 径向渐变挖光，灯笼半径随油量从 190px 收缩到 72px——油量条不是 HUD 数字，是玩家眼前的光圈本身。
  • AI 可读性优先：怪物的每一态都要能被玩家"读"出意图，恐惧来自信息而非随机。
  • 数值即体验：所有资源点位、消耗速率、AI 速度都以"玩家最坏情况 3 秒反应窗"为约束反推。

二、核心机制设计

2.1 光即资源即风险

三种用途互相冲突：视野（照明）、生存（油尽视野坍缩）、安全区建设（注灯）。玩家时刻处于"花还是存"的决策中，灯油消耗速率分三档：长明灯区 0.02/秒、黑暗静止 0.10/秒、黑暗移动 0.63/秒，追猎者贴身额外抽油 25/秒——风险等级直接读在油表上。

设计要点：地图放 6 份灯油，是最低通关需求 3 份的 2 倍。冗余不是宽松，是给玩家"选择在哪盏灯点火"的策略空间；火柴上限 8 根、照明驱退 2.4 秒，作为爆发性资源与灯油的持续消耗形成节奏对比。

2.2 四态 AI：恐惧来自可读性

状态速度表现离开条件
游荡52 px/s暗红微光、缓慢漂移听见脚步 / 近距感知 → 察觉
察觉38 px/s眼睛转金、停顿望向声源，警告 1.8 秒警告满 1.8s → 追猎；玩家进稳定光区 → 丢失
追猎118 px/s猩红亮眼、拖影、持续压迫提示火柴击退 / 玩家入光区 → 丢失；接触且无光照 → 失败
丢失70 px/s灰白闪烁、背离玩家撤退2.8 秒后回游荡

察觉阶段固定 1.8 秒警告窗，追猎开始时敌我距离强制 ≥390px（按相对速度估算追上需 >3 秒）——恐惧不靠突脸，靠"看见它开始找你"。

2.3 地图与叙事

1440×900 逻辑画布，三组带门洞隔墙划出西厢 / 正堂 / 东厢 / 雨院 / 停棺房。5 张字条（51–54 字/张）拼出"规矩—前任—失名—循声—鸡鸣约定"的完整怪谈，集齐后解锁隐藏胜利文案"灯以你名"。阅读字条时暂停实时系统——叙事不被惩罚打断。

三、机制演化：11 轮打磨实录

本项目最重要的设计过程发生在验收后：凯迪试玩 → 反馈 → 迭代，共 11 轮。以下是最关键的演化链：

终局"灭灯战"六轮迭代（秒杀 → 守灯等待 → 防呆滞 → 扑击 → 规则定稿 → 手感）：

1. 初版三灯点亮后倒计时 5 分钟无事可做——"等待期是节奏设计的死角"；

2. 加时间加速 + 强制追杀，却被长明灯安全区豁免反噬成"站桩挂机 30 秒"——平时仁慈的规则在终局成了后门；

3. 按用户方案推翻重做"灭灯战"：怪物新增第五状态，逐盏掐灯（3 秒读条+红色进度弧），玩家守灯/重燃/打断周旋；

4. 按用户口语规则定稿：重燃免费、终局不死、全灭不追杀（它守在熄灯旁阻挠重燃，形成"点灯—驱赶—再点灯"节奏）、鸡鸣即胜；

5. 手感：掐灯速度 46→80，目标锁定制 + 重燃免战 8 秒 + 30% 随机目标，消除"每帧贪心选最近"的呆滞；

6. 终局扑击：玩家靠太近它就转追逐（118px/s，撞上 25 油/秒），守灯从站桩变成"进-逼退-被扑-拉开-再进"循环。

教训沉淀：

"等待期"是节奏设计的死角 任何超过 30 秒的无事可做阶段都应转化为压力递增的终局段落——尤其是胜利前夜。
氛围游戏的"黑"必须有信息梯度 黑暗层调了三轮才定位真根因：不是遮罩不够透，而是世界基色本身画得太黑。地标光晕、道具微光、行为触发的三步教学是可玩性下限，不是可选项。调层不调色等于没调。
用户口语规则=可验证的验收项 "不需要灯油""不会死亡""坚持 30 秒"——每句口语描述都是一条可仿真验证的验收项。终局改版先做逻辑仿真再上真机：代码断言只能证明代码存在，仿真才能证明体验成立。
安全机制与威胁机制要成对设计 免死+无威胁=没有压力。终局的"安全区豁免"要么明确失效、要么给出替代压力，不能留成挂机后门。

3.2 BFS 寻路两轮（卡墙根治）

怪物隔墙直线移动卡死 → 新增视线检查 + 粗网格 BFS（20px 格，0.4s 重算），全图 BFS 单次 0.13ms。第一版仍有 5.2% 场景"判通但走不通"，node 仿真定位两个叠加缺陷：膨胀半径 6px < 实体半径 12px（视线通的通道实体过不去）、采样循环不含终点。修复后 103,797 条场景 0 卡死。

碰撞检测的膨胀半径必须 ≥ 实体半径 射线采样必须包含端点，且边界判定与移动判定用同一套区间约定，否则两套几何判定必有缝隙。

四、技术实现

  • 零依赖单文件 HTML + Canvas 2D：场景层 → 黑暗遮罩层 → destination-out 挖光 → screen 混合信标（画在黑暗层之上，全图可定位）。
  • 三层教学：菜单三步目标流程条 + 键位速查 + 纸页「守夜规程」详细教学，全部复用 modal 零新依赖。
  • localStorage 三个键：图鉴 / 最佳纪录 / 减少动态效果设置；单局状态不存。
  • 验证体系：18 项断言 + node 逻辑仿真（挂机不守 38.7s 三灯全灭 / 站灯旁固守 40s 成功）+ 10 万+ 条寻路场景扫描。

五、验证与上线
